# Ревью документа

## Содержание

- Порядок ревью
- Характеристики качества
- Проверка самодостаточной страницы
- Ревью записей
- Формат отчёта

Ревью идёт от крупного к мелкому. Если не тот тип или не тот каркас, правка предложений пропадёт, поэтому в отчёте крупные проблемы стоят первыми.

## Порядок ревью

1. **Тип.** Назовите читателя и тип. Если на странице смешаны типы (шаги вперемешку с обоснованием архитектуры, tutorial, который уходит в reference), первое замечание предлагает разделить страницу.
2. **Каркас.** Сравните разделы с каркасом типа. Отметьте недостающие, лишние и стоящие не на своём месте разделы.
3. **Факты.** Сверьте команды, флаги, значения по умолчанию, версии и ссылки с кодом или с источником, на который указал пользователь. Где можно, запустите команды. Отметьте каждый факт, который не удалось проверить.
4. **Абзацы и связность.** Каждый абзац начинается со своей темы; предложения идут от известного к новому; одно понятие везде называется одним термином.
5. **Предложения.** Персонажи в подлежащем, действия в глаголе, нет случайных отглагольных существительных, разумная длина.
6. **Слова.** Стоп-слова, LLM-паттерны, оценки, которые должны стать фактами.

Перед шагом 4 запустите скрипт проверки на файле и используйте его вывод на шагах 4–6.

## Характеристики качества

Книга *Developing Quality Technical Information* (IBM Press) делит девять характеристик качества на три группы. Используйте их как оси ревью после прохода по порядку, чтобы найти то, что проход пропустил.

| Группа | Характеристика | Вопрос для ревьюера |
|---|---|---|
| Легко использовать | Ориентация на задачу | Страница построена вокруг того, что делает читатель? |
| Легко использовать | Точность | Каждый факт верен и проверен? |
| Легко использовать | Полнота | Есть всё, что нужно читателю, и ничего лишнего? |
| Легко понять | Ясность | Каждое предложение можно прочитать только одним способом? |
| Легко понять | Конкретность | Есть примеры, числа и имена там, где они нужны читателю? |
| Легко понять | Стиль | Голос, термины и тон единообразны и подходят типу? |
| Легко найти | Организация | Порядок совпадает с путём читателя? |
| Легко найти | Находимость | Читатель находит страницу и раздел, пробегая текст глазами или через поиск? |
| Легко найти | Визуальная выразительность | Таблицы, диаграммы и скриншоты помогают и имеют текстовые эквиваленты? |

## Проверка самодостаточной страницы

Марк Бейкер в книге *Every Page is Page One* описывает страницу, которая работает для читателя, пришедшего из поиска. Проверьте семь её признаков:

| Признак | Проверка |
|---|---|
| Самодостаточна | Страница работает без чтения предыдущей и следующей? |
| Узкая и конкретная цель | Страница решает одну задачу? |
| Соответствует типу | Она следует каркасу своего типа? |
| Задаёт контекст | Первые строки говорят, что это и для кого? |
| Считает читателя подготовленным | Она ссылается на справочный материал и оставляет обучение другим страницам? |
| Держит один уровень | Уровень детализации одинаков по всей странице? |
| Богата ссылками | Есть ссылки на связанные страницы, термины и предварительные условия? |

## Ревью записей

ADR, postmortem или опубликованная запись в changelog фиксируют момент. Ревью их не переписывает. Если содержание устарело, замечание предлагает новую запись, которая заместит старую. Старая запись получает изменение статуса в одну строку со ссылкой на новую. В записи исправляют только опечатки и битые ссылки.

## Формат отчёта

Выдайте замечания таблицей, крупные проблемы первыми. Каждая строка называет одну проблему.

| Где | Что | Как исправить |
|---|---|---|
| Раздел «Установка», шаг 3 | Команда использует `--force`, который убрали во второй версии инструмента | Заменить на `tool install --replace <PACKAGE>` |
| Вся страница | Шаги перемешаны с обоснованием архитектуры | Разделить на how-to и explanation, связать ссылками |

«Где» — название раздела, заголовок или цитата, которую автор найдёт поиском. «Что» описывает проблему как факт. «Как исправить» даёт текст замены или конкретное действие. После таблицы дайте вердикт в одну строку: готово; готово после перечисленных правок; сначала нужна перестройка. Переписывайте страницу, только если об этом просит пользователь.
