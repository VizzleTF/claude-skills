# Reference

Reference описывает части системы: параметры, поля, команды, эндпоинты, лимиты. Читатель находит один факт и уходит.

## Когда это он и когда нет

Reference нужен для всего, что читатель ищет, а не читает подряд: ключей конфигурации, эндпоинтов API, флагов CLI, кодов ошибок, лимитов.

Выберите другой тип, если:

- читателю нужны шаги: how-to;
- читателю нужны причины архитектурного решения: explanation;
- факты живут рядом с кодом и их читают те, кто вызывает код: docstring.

## Каркас

Однородные пункты. У каждого пункта одни и те же поля в одном порядке:

| Поле | Содержание |
|---|---|
| Имя | Точное имя в том виде, как его набирают: `timeout`, `--dry-run`, `GET /users`. |
| Тип | Тип данных или вид значения. |
| По умолчанию | Значение, когда ничего не задано, или «обязательный». |
| Пределы | Допустимый диапазон, единицы, форматы. |
| Пример | Рабочее значение или вызов. |

Если имя говорит мало, добавьте после него одно поясняющее предложение. Располагайте пункты так, как читатель ищет: по алфавиту или в порядке файла либо API.

Где можно, генерируйте reference из кода или схемы, чтобы он не отставал от системы.

## Голос и глаголы

Изъявительное наклонение, третье лицо: «Задаёт тайм-аут соединения», «Возвращает список пользователей». Подлежащее здесь тот объект, который описан.

## Объём

Один пункт на элемент системы, и каждый пункт не длиннее своих полей: строка таблицы или несколько строк, без прозы между пунктами. Длина страницы следует за размером системы (эмпирика).

## Отличия от общих правил

- **Третье лицо вместо «вы».** Reference описывает систему. Пишите «Флаг отключает кеширование», а форму `С помощью флага вы можете отключить кеширование` не используйте.
- **Только факты.** В reference нет советов и рекомендуемых практик. Совет уходит в how-to.

## Запрещено

- Советы, мнения и лучшие практики.
- Пункты, в которых нет полей, которые есть у остальных.
- Подразумеваемые единицы: пишите `30s` или «секунды».
- Абзацы прозы между пунктами.
- Пересказ шагов.

## Чек-лист типа

- [ ] У каждого пункта одни и те же поля в одном порядке.
- [ ] Каждое значение по умолчанию и каждая единица указаны.
- [ ] Каждый пример работает как написан.
- [ ] Глаголы в изъявительном наклонении, в третьем лице.
- [ ] Советов нет.
- [ ] Порядок пунктов совпадает с тем, как читатель ищет.
