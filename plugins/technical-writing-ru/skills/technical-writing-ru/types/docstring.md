# Docstring и комментарий в коде

Docstring документирует интерфейс для тех, кто его вызывает. Комментарий в коде объясняет следующему сопровождающему то, чего не показывает сам код.

## Когда это он и когда нет

Docstring пишут у каждого публичного модуля, класса, функции и метода. Комментарий ставят там, где код сам оставляет вопрос: почему выбран такой подход, какой инвариант держится, что сломается, если эту строку изменить.

Выберите другой тип, если:

- нужен сценарий на несколько функций, по шагам: how-to;
- нужен полный список параметров публичного API: reference, по возможности сгенерированный из docstring;
- нужны устройство модуля и его история: explanation или ADR.

## Каркас

Docstring:

1. Строка-резюме: что делает функция, в одну строку.
2. Пустая строка, затем то, чего не видно из сигнатуры: единицы, допустимые диапазоны, побочные эффекты, исключения, потокобезопасность.
3. Параметры и возвращаемое значение в формате, принятом в проекте.
4. Пример, если способ вызова неочевиден.

Комментарий занимает одну-три строки над кодом, который объясняет. John Ousterhout среди прочих видов различает комментарии интерфейса и комментарии реализации. Комментарий интерфейса описывает то, что нужно вызывающему, то есть контракт. Комментарий реализации описывает, как и почему код делает свою работу внутри. Не смешивайте их: интерфейс описывает docstring, реализацию описывают комментарии в теле.

## Голос и глаголы

В Python следуйте PEP 257. Строка-резюме предписывает эффект как команду, `Return the user's ID`, и не описывает его в форме `Returns the user's ID`. PEP 257 также советует, чтобы однострочный docstring не повторял сигнатуру. В docstring на русском повелительному наклонению соответствует инфинитив: «Вернуть ID пользователя».

В других языках следуйте конвенции проекта. Javadoc использует третье лицо: `Returns the user's ID`, по-русски «Возвращает ID пользователя».

## Объём

Одна строка, если имя и сигнатура говорят остальное. Больше строк только для фактов, которые вызывающий иначе узнал бы из кода или из сбоя (эмпирика).

## Отличия от общих правил

- **Повелительное резюме в Python.** Reference описывает пункт в третьем лице. Docstring в Python сообщает тот же факт командой, как советует PEP 257.
- **Почему важнее что.** Комментарий в теле функции даёт причину кода. Что делает код, видно из самого кода.

## Запрещено

- Пересказ сигнатуры: `Принимает строку и возвращает int.`
- Комментарии, которые пересказывают код построчно: `# увеличить i`.
- Комментарии с историей: `изменил X в марте`. Историю хранит система контроля версий.
- Единицы, диапазоны или побочные эффекты, которые читатель должен угадать.
- Docstring, который расходится с кодом.

## Чек-лист типа

- [ ] Строка-резюме помещается в одну строку.
- [ ] В Python резюме в повелительном наклонении; в русском docstring принят инфинитив.
- [ ] Ничто не повторяет сигнатуру.
- [ ] Единицы, диапазоны, побочные эффекты и исключения названы.
- [ ] Комментарии интерфейса и реализации разделены.
- [ ] Каждый комментарий говорит то, чего не говорит код.
