# Conventions

Conventions записывают правила, которым следует команда: стиль кода, именование, ревью, коммиты, устройство API. Читатель входит в команду и обязан эти правила применять.

## Когда это он и когда нет

Conventions нужны для правил, которые касаются каждого участника и которые может проверить ревьюер.

Выберите другой тип, если:

- нужно одно решение с контекстом и компромиссами: ADR. Правило из conventions может ссылаться на ADR, который его ввёл;
- нужны шаги настройки инструмента: how-to;
- нужна предыстория того, почему код организован именно так: explanation.

## Каркас

Каждое правило оформлено одним пунктом:

1. Правило одним предложением, со словом обязательности.
2. Зачем: причина в одном-двух предложениях.
3. Пример: сначала плохо, потом хорошо.

Группируйте правила по областям. Нумеруйте их, чтобы ревьюер мог сослаться на правило: «См. N-4».

## Голос и глаголы

Обязательность задаёт постоянная шкала из трёх уровней. Она соответствует ключевым словам RFC 2119:

| Слово | RFC 2119 | Значение |
|---|---|---|
| обязательно, запрещено | MUST, MUST NOT | Требование. Ревьюер блокирует изменение. |
| рекомендуется, не рекомендуется | SHOULD, SHOULD NOT | Совет. Для исключения нужна названная причина. |
| можно | MAY | Разрешено. Подходит любой выбор. |

В начале страницы скажите, что эти слова несут именно такие значения. В каждом правиле стоит одно слово из шкалы. Голое повелительное наклонение не используется: по нему читатель не отличит требование от совета.

## Объём

Один пункт на правило, по нескольку строк. Правило, которому нужна страница обоснования, принадлежит ADR, а правило ссылается на него (эмпирика).

## Отличия от общих правил

- **Правило без причины не принимается.** Каждое правило говорит, зачем оно. Читатель, который знает причину, применит правило и там, куда пример не дотягивается.

## Запрещено

- Правила без причины.
- Слова обязательности вне шкалы: `старайтесь`, `в идеале`, `желательно`.
- Правила, которые ревьюер не может проверить: `пишите чистый код`.
- Примеры, где показан только хороший вариант.

## Чек-лист типа

- [ ] У каждого правила есть слово обязательности из шкалы.
- [ ] У каждого правила есть причина.
- [ ] У каждого правила есть плохой и хороший пример.
- [ ] Правила пронумерованы и сгруппированы по областям.
- [ ] Ревьюер может проверить каждое правило.
