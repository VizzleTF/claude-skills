# ADR-0012: Advisory locks в PostgreSQL вместо Redis-блокировок в планировщике

**Статус:** предложено, 2026-09-28
**Автор:** команда планировщика

## Контекст

Планировщик Veyrun работает в трёх репликах, и каждую задачу должна выполнить ровно одна из них. Сейчас блокировки берутся через Redlock поверх Redis. Во втором квартале 2026 года задача дважды запустилась повторно. Оба случая пришлись на переключение Redis на реплику.

## Решение

Мы будем брать блокировку на каждую задачу вызовом `pg_try_advisory_lock(job_id)` в PostgreSQL 16, который у нас уже есть. Redis для блокировок планировщика мы использовать перестанем.

## Последствия

Планировщик больше не зависит от Redis. Блокировка живёт, пока живо соединение, которое её взяло, поэтому в пуле нужно держать три соединения под блокировки. Если PostgreSQL лежит, планировщик останавливается. Мы принимаем это, потому что задачи пишут в ту же базу и без неё не работают.

## Рассмотренные альтернативы

- etcd leases: отклонили, потому что ради них пришлось бы сопровождать новый кластер.
- Kubernetes Lease: отклонили, потому что он выбирает одного лидера на весь планировщик, а нам нужна блокировка на каждую задачу, иначе пропадает параллельность.

# ADR 0012: Планировщик Veyrun переходит с Redis-блокировок на advisory locks PostgreSQL

- **Статус:** предложено
- **Дата:** 2026-09-28
- **Автор:** команда планировщика

## Решение

Планировщик берёт блокировку на задачу через `pg_try_advisory_lock(job_id)` в PostgreSQL 16, который у нас уже есть. Redlock поверх Redis убираем.

## Контекст

Планировщик работает в трёх репликах. Каждую задачу должна выполнить ровно одна из них.

Сейчас для этого используется Redlock поверх Redis. Во втором квартале 2026 года задача дважды запускалась дважды. Оба раза это случилось при переключении Redis на реплику.

## Последствия

**Что получаем**

- Планировщик больше не зависит от Redis.
- Блокировка привязана к соединению с PostgreSQL. Она живёт, пока живо соединение, поэтому при переключении Redis дубли задач не возникают.

**Чем платим**

- В пуле нужно держать три соединения, отведённые под блокировки.
- Если PostgreSQL недоступен, планировщик останавливается. Это приемлемо: задачи пишут в эту же базу и без неё не работают.

## Рассмотренные альтернативы

| Вариант | Почему отказались |
|---|---|
| etcd leases | Нужен новый кластер, его придётся сопровождать. |
| Kubernetes Lease | Выбирает одного лидера на весь планировщик, а нам нужна блокировка на каждую задачу. С одним лидером пропадает параллельность. |
