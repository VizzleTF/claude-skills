# Агент Orbisk не работает: ошибки из журнала

Найдите на странице код ошибки из журнала агента (`E101`, `E204`, `E310`, `E415`) и выполните шаги под ним. Агент Orbisk собирает метрики на серверах.

Чтобы увидеть ошибки, выведите журнал агента:

```sh
journalctl -u orbisk-agent
```

## `E101: token rejected (401)`

**Причина:** токен истёк (он действует 90 дней) или его отозвали.

1. Создайте новый токен:
   ```sh
   orbisk token create
   ```
2. Впишите его в поле `token` в файле `/etc/orbisk/agent.yaml`.
3. Перезапустите агент:
   ```sh
   systemctl restart orbisk-agent
   ```

## `E204: clock skew 312s exceeds 120s`

Число секунд в вашем сообщении может отличаться.

**Причина:** часы сервера расходятся с часами Orbisk больше чем на 120 секунд.

Включите синхронизацию времени по NTP:

```sh
timedatectl set-ntp true
```

## `E310: spool full (512 MiB)`

**Причина:** агент не может подключиться к `ingest.orbisk.example:443`. Буфер (spool), где агент хранит неотправленные метрики, заполнен, поэтому старые метрики удаляются.

**Что делать:** восстановите сетевой доступ к `ingest.orbisk.example:443`.

Буфер можно увеличить параметром `spool_max_mb` в `/etc/orbisk/agent.yaml` (максимум 4096). Это лишь отсрочит потерю метрик: пока доступа нет, буфер заполнится снова.

## `E415: unknown collector "nginx_plus"`

Имя коллектора в вашем сообщении может быть другим.

**Причина:** плагин с этим коллектором не установлен.

Установите плагин, подставив имя из сообщения:

```sh
orbisk plugins install nginx_plus
```

## Проверка после исправления

Следите за журналом. Если ошибка не появляется снова, проблема решена:

```sh
journalctl -u orbisk-agent -f
```
