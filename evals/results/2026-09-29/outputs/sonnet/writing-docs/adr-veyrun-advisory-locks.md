# ADR 0012: Планировщик Veyrun переходит с Redis-блокировок на advisory locks PostgreSQL

- **Статус:** предложено
- **Дата:** 2026-09-28
- **Автор:** команда планировщика

## Решение

Планировщик берёт блокировку на задачу через `pg_try_advisory_lock(job_id)` в PostgreSQL 16, который у нас уже есть. Redlock поверх Redis убираем.

## Контекст

Планировщик работает в трёх репликах. Каждую задачу должна выполнить ровно одна из них.

Сейчас для этого используется Redlock поверх Redis. Во втором квартале 2026 года задача дважды запускалась дважды. Оба раза это случилось при переключении Redis на реплику.

## Последствия

**Что получаем**

- Планировщик больше не зависит от Redis.
- Блокировка привязана к соединению с PostgreSQL. Она живёт, пока живо соединение, поэтому при переключении Redis дубли задач не возникают.

**Чем платим**

- В пуле нужно держать три соединения, отведённые под блокировки.
- Если PostgreSQL недоступен, планировщик останавливается. Это приемлемо: задачи пишут в эту же базу и без неё не работают.

## Рассмотренные альтернативы

| Вариант | Почему отказались |
|---|---|
| etcd leases | Нужен новый кластер, его придётся сопровождать. |
| Kubernetes Lease | Выбирает одного лидера на весь планировщик, а нам нужна блокировка на каждую задачу. С одним лидером пропадает параллельность. |
