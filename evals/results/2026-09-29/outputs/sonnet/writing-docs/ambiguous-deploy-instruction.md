# Деплой Moorfen API

Как выкатить новую версию Moorfen API в stage и prod, проверить работоспособность и откатиться при проблемах.

## Окно деплоя

В prod можно выкатывать только с понедельника по четверг, 10:00–17:00 МСК. Кнопка `promote-prod` вне этого окна не сработает (см. таблицу ошибок).

## 1. Собрать и выкатить в stage

1. Запушьте тег вида `vX.Y.Z`:
   ```sh
   git tag v1.4.2
   git push origin v1.4.2
   ```
2. CI соберёт образ и сам выкатит его в stage — дальнейших действий не требуется.

Тег должен точно соответствовать шаблону `vX.Y.Z`. Другой формат (например, `v1.2`) CI не запустит — молча, без ошибки.

## 2. Выкатить в prod

1. В CI нажмите `promote-prod` для нужного тега.
2. Деплой требует ручного подтверждения и проходит только в окне (Пн–Чт, 10:00–17:00 МСК).

## 3. Проверить, что сервис жив

После выкатки в stage или prod выполните:
```sh
curl -fsS https://moorfen.example/healthz
```
Успех — ответ `ok`. Любой другой ответ — сервис нездоров, см. таблицу ошибок.

## Откат

Нажмите `promote-prod` у предыдущего (последнего рабочего) тега — так же, как для обычной выкатки в prod.

## Частые ошибки

| Сообщение / симптом | Причина | Что делать |
|---|---|---|
| `deploy window closed: allowed Mon-Thu 10:00-17:00 MSK` | `promote-prod` нажали вне окна | Дождаться окна (Пн–Чт, 10:00–17:00 МСК) и нажать `promote-prod` заново |
| Пайплайн не запускается после пуша тега | Тег не соответствует шаблону `vX.Y.Z` (например, `v1.2`) | Удалить тег: `git push --delete origin <TAG>`, запушить тег в правильном формате |
| `healthz` возвращает `degraded: db` | Сервис не видит базу данных | Откатиться через `promote-prod` на предыдущем теге, сообщить в #moorfen-dev |
| Сборка падает с `COPY failed: file not found in build context` | В репозитории нет файла, на который ссылается Dockerfile | Исправить пути в Dockerfile или добавить файл, запушить новый тег |
