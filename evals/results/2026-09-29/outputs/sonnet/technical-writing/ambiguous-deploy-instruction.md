# Выкати версию Moorfen API

Инструкция для тех, кто выкатывает новую версию сервиса: сначала в stage, затем в prod.

**Требования:** права на push тегов в репозиторий и на кнопку `promote-prod` в CI.

1. Создай тег по шаблону `vX.Y.Z`, например `v1.2.3`: `git tag <TAG>`.
2. Запушь тег: `git push origin <TAG>`. CI соберёт образ и сам выкатит его в stage.
3. Если сейчас не время с понедельника по четверг, 10:00–17:00 по Москве, дождись начала окна: вне окна `promote-prod` падает.
4. Нажми `promote-prod` в CI для этого тега. Выкатка в prod идёт только после ручного подтверждения.
5. Проверь сервис: `curl -fsS https://moorfen.example/healthz`. Ответ должен быть `ok`.

## Если что-то пошло не так

- **`promote-prod` падает с `deploy window closed: allowed Mon-Thu 10:00-17:00 MSK`.** Дождись окна и перезапусти `promote-prod`.
- **Пайплайн не запустился после push.** Тег не подходит под шаблон `vX.Y.Z` (например, `v1.2`), и пайплайн молча его пропускает. Удали тег: `git push --delete origin <TAG>`. Запушь тег с правильным именем.
- **Сборка падает с `COPY failed: file not found in build context`.** В репозитории нет файла, на который ссылается Dockerfile. Поправь пути в Dockerfile и запушь исправление с новым тегом.
- **`healthz` отвечает `degraded: db`.** Сервис не видит базу. Откатись (см. ниже) и напиши в #moorfen-dev.

## Откат

Перезапусти `promote-prod` у предыдущего тега. После отката снова выполни `curl -fsS https://moorfen.example/healthz`: ответ должен быть `ok`.
