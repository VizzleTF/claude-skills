# Агент Orbisk не работает: ошибки из журнала

Найдите в таблице сообщение из журнала агента. Журнал читайте командой `journalctl -u orbisk-agent`.

| Сообщение | Причина | Действие |
|---|---|---|
| `E101: token rejected (401)` | Токен истёк (он живёт 90 дней) или его отозвали. | Выпустите новый токен и перезапустите агент. [Шаги](#e101-token-rejected-401) |
| `E204: clock skew 312s exceeds 120s` | Часы сервера расходятся с часами Orbisk больше чем на 120 секунд. Число секунд в вашем сообщении может быть другим. | Включите NTP: `timedatectl set-ntp true` |
| `E310: spool full (512 MiB)` | Агент давно не может подключиться к `ingest.orbisk.example:443`. Буфер заполнен, и старые метрики выбрасываются. | Верните серверу сетевой доступ к этому адресу. [Подробнее](#e310-spool-full-512-mib) |
| `E415: unknown collector "nginx_plus"` | Плагин коллектора не установлен. Имя коллектора в вашем сообщении может быть другим. | Установите плагин: `orbisk plugins install nginx_plus`. Подставьте имя из своего сообщения. |

## E101: token rejected (401)

1. Создайте новый токен:

   ```bash
   orbisk token create
   ```

2. Впишите его в поле `token` в `/etc/orbisk/agent.yaml`.
3. Перезапустите агент:

   ```bash
   systemctl restart orbisk-agent
   ```

## E310: spool full (512 MiB)

Сначала восстановите доступ с сервера к `ingest.orbisk.example` на порт 443. Метрики, которые агент уже выбросил из буфера, вернуть нельзя.

Если сеть бывает недоступна подолгу, увеличьте буфер параметром `spool_max_mb`. Максимум — 4096.
