# Агент Orbisk не работает: расшифровка ошибок

Агент Orbisk собирает метрики на сервере. Если метрики не приходят, посмотрите лог агента:

```bash
journalctl -u orbisk-agent -n 100
```

Найдите в выводе строку с ошибкой, скопируйте её начало (например, `E101`) и найдите на этой странице.

| Ошибка в логе | Что случилось | Раздел |
|---|---|---|
| `E101: token rejected (401)` | Токен истёк или отозван | [E101](#e101) |
| `E204: clock skew … exceeds 120s` | Часы сервера разошлись с нашими | [E204](#e204) |
| `E310: spool full (512 MiB)` | Агент не достучался до сервера, буфер переполнен | [E310](#e310) |
| `E415: unknown collector "…"` | Не установлен плагин коллектора | [E415](#e415) |

Другой ошибки нет в списке? Напишите в поддержку и приложите вывод `journalctl -u orbisk-agent -n 100`.

---

## <a id="e101"></a>`E101: token rejected (401)`

**Причина.** Сервер не принял токен агента. Токен живёт 90 дней, поэтому он мог истечь. Ещё его могли отозвать.

**Что делать.**

1. Создайте новый токен:
   ```bash
   orbisk token create
   ```
2. Впишите его в поле `token` в файле `/etc/orbisk/agent.yaml`.
3. Перезапустите агент:
   ```bash
   systemctl restart orbisk-agent
   ```

---

## <a id="e204"></a>`E204: clock skew 312s exceeds 120s`

Число секунд у вас может быть другим, суть та же.

**Причина.** Часы на сервере отстают или спешат относительно наших больше чем на 120 секунд.

**Что делать.** Включите синхронизацию времени по NTP:

```bash
timedatectl set-ntp true
```

---

## <a id="e310"></a>`E310: spool full (512 MiB)`

**Причина.** Агент давно не может подключиться к `ingest.orbisk.example:443`. Метрики копятся в локальном буфере (spool). Буфер заполнился, и агент выкидывает старые метрики. Пока связи нет, эти метрики теряются.

**Что делать.**

1. Верните серверу сетевой доступ к `ingest.orbisk.example` на порт 443. Проверьте файрвол, прокси и правила исходящего трафика. Проверить доступность можно так:
   ```bash
   curl -sv -o /dev/null https://ingest.orbisk.example:443
   ```
2. Если нужен запас на случай долгих обрывов связи, увеличьте буфер параметром `spool_max_mb`. Максимум — 4096.

Увеличенный буфер только откладывает потерю метрик. Восстановить связь всё равно нужно.

---

## <a id="e415"></a>`E415: unknown collector "nginx_plus"`

Имя коллектора у вас может быть другим.

**Причина.** В конфигурации включён коллектор, а его плагин на сервере не установлен.

**Что делать.** Установите плагин, подставив имя из сообщения об ошибке:

```bash
orbisk plugins install nginx_plus
```
