# Соглашения по Terraform-коду платформы Brannock

Документ описывает, как мы пишем Terraform-код на платформе Brannock и почему. Читайте его перед первым PR. Ревьюеры опираются на него.

## Уровни правил

| Уровень | Что значит |
|---|---|
| **Обязательно** | Нарушение блокирует merge. Исключений нет. |
| **Желательно** | Делаем по умолчанию. Отступление допустимо, если в PR объяснено, почему. |
| **Можно** | Допустимый приём. Решает автор. |

| # | Правило | Уровень |
|---|---|---|
| 1 | Версии провайдеров закрепляем через `~>` | Обязательно |
| 2 | Имена ресурсов только в `snake_case` | Обязательно |
| 3 | State не коммитим, только удалённый бэкенд | Обязательно |
| 4 | У каждого ресурса теги `owner` и `cost_center` | Обязательно |
| 5 | Один модуль на каталог и README в каждом модуле | Желательно |
| 6 | Общие теги выносим в `locals` | Можно |

Примеры ниже написаны для AWS, но правила не зависят от провайдера. Имена бакетов, команд и центров затрат в примерах условные.

## 1. Версии провайдеров закрепляем через `~>` (обязательно)

**Правило.** Каждый провайдер в `required_providers` указывается с `source` и с версией через оператор `~>`.

**Почему.** Без ограничения версии `init` может выбрать любую свежую версию провайдера, в том числе мажорную с ломающими изменениями. Тогда провайдер обновляется молча, и `plan` внезапно показывает диф, которого никто не писал. Ограничение `~>` делает обновление осознанным: вы сами поднимаете версию в коде, и это видно в PR.

**Как читать `~>`:**
- `~> 5.40` разрешает `>= 5.40` и `< 6.0`, то есть новые минорные версии, но не мажорные.
- `~> 5.40.0` разрешает `>= 5.40.0` и `< 5.41.0`, то есть только патчи.

**Плохо:**

```hcl
terraform {
  required_providers {
    aws = {
      source = "hashicorp/aws"          # версии нет: подтянется что угодно
    }
    random = {
      source  = "hashicorp/random"
      version = ">= 3.0"                # нижняя граница без верхней: мажорное обновление пройдёт молча
    }
  }
}
```

**Хорошо:**

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.40"
    }
    random = {
      source  = "hashicorp/random"
      version = "~> 3.6"
    }
  }
}
```

## 2. Имена ресурсов только в `snake_case` (обязательно)

**Правило.** Локальное имя ресурса, то есть второй лейбл в `resource "тип" "имя"`, пишется строчными буквами, слова разделяются `_`. Дефисы, заглавные буквы и camelCase не используем.

**Почему.** Локальное имя входит в адрес ресурса (`aws_s3_bucket.logs_bucket`). Этот адрес мы видим в коде, в выводе `plan` и в `terraform state`, и по нему же ищем. Если везде один стиль, строка из плана находится в коде обычным поиском, и наоборот. Когда стили смешаны, вы не знаете, искать `logs-bucket`, `logsBucket` или `LogsBucket`.

Правило про идентификатор в Terraform. Атрибуты вроде `name` или `bucket`, которые попадают в облако, оно не затрагивает.

**Плохо:**

```hcl
resource "aws_s3_bucket" "Logs-Bucket" { ... }
resource "aws_s3_bucket" "logsBucket" { ... }
resource "aws_sqs_queue" "OrdersQueue" { ... }
```

**Хорошо:**

```hcl
resource "aws_s3_bucket" "logs_bucket" { ... }
resource "aws_sqs_queue" "orders_queue" { ... }
```

Поиск `aws_s3_bucket.logs_bucket` теперь одинаково работает и по коду, и по выводу `plan`.

## 3. State не коммитим, только удалённый бэкенд (обязательно)

**Правило.** Файлы state (`*.tfstate`, `*.tfstate.*`) никогда не попадают в репозиторий. State живёт только в удалённом бэкенде, который настроен в блоке `backend`.

**Почему.**
- **Секреты.** В state лежат значения атрибутов ресурсов, в том числе пароли, ключи и токены. Всё, что закоммитили, остаётся в истории git.
- **Расхождение копий.** Если state есть и в репозитории, и в бэкенде (или у нескольких людей локально), копии расходятся. Следующий `apply` работает по устаревшему состоянию и может пересоздать или удалить живые ресурсы.

Правило касается только state. Файл `.terraform.lock.hcl` под него не подпадает.

**Плохо:**

```text
infra/
├── main.tf
├── terraform.tfstate          # state в репозитории
└── terraform.tfstate.backup
```

```hcl
# блока backend нет: state создаётся локально рядом с кодом
terraform {
  required_providers { ... }
}
```

**Хорошо:**

```hcl
terraform {
  backend "s3" {
    bucket  = "brannock-tfstate"                      # условное имя
    key     = "platform/network/terraform.tfstate"
    region  = "eu-central-1"
    encrypt = true
  }
}
```

```gitignore
# .gitignore
*.tfstate
*.tfstate.*
.terraform/
```

**Если state всё же закоммитили.** Немедленно сообщите команде. Считайте все секреты из этого state скомпрометированными и перевыпустите их. Затем уберите файл из репозитория и из истории. Простого удаления в новом коммите недостаточно, потому что старые коммиты сохраняют содержимое.

## 4. У каждого ресурса теги `owner` и `cost_center` (обязательно)

**Правило.** Каждый ресурс, который поддерживает теги, создаётся с тегами `owner` и `cost_center`.

**Почему.**
- По `cost_center` считают расходы: без тега затраты не привязать к статье бюджета.
- По `owner` находят владельца: когда ресурс сломался, дорожает или про него никто не помнит, тег отвечает на вопрос «кому писать».

**Плохо:**

```hcl
resource "aws_instance" "app_server" {
  ami           = var.ami_id
  instance_type = "t3.medium"

  tags = {
    Name = "app-server"      # владельца и центра затрат нет
  }
}

resource "aws_sqs_queue" "orders_queue" {
  name = "orders"            # тегов нет совсем
}
```

**Хорошо:**

```hcl
resource "aws_instance" "app_server" {
  ami           = var.ami_id
  instance_type = "t3.medium"

  tags = {
    Name        = "app-server"
    owner       = "team-payments"      # условное значение
    cost_center = "cc-1234"            # условное значение
  }
}

resource "aws_sqs_queue" "orders_queue" {
  name = "orders"

  tags = {
    owner       = "team-payments"
    cost_center = "cc-1234"
  }
}
```

Ключи тегов пишем ровно так: `owner` и `cost_center`, строчными буквами. Варианты вроде `Owner` или `cost-center` отчёты не увидят.

## 5. Один модуль на каталог и README в каждом модуле (желательно)

**Правило.** Каждый модуль лежит в своём каталоге. В каталоге один модуль, а не несколько, перемешанных в одном наборе `.tf`-файлов. В каждом модуле есть `README.md`.

**Почему.** Модуль должен быть понятен без чтения кода: что он создаёт, какие у него входы и выходы, как его подключить. Когда в каталоге лежит один модуль, границы очевидны: каталог и есть модуль, его можно вызвать через `source = "./modules/<имя>"`.

**Что в README:**
- что модуль делает и для чего он нужен;
- входные переменные (что обязательно, что имеет значение по умолчанию);
- выходные значения;
- короткий пример вызова.

**Плохо:**

```text
modules/
└── stuff/                 # в одном каталоге смешаны два разных модуля
    ├── main.tf            # и VPC, и очередь SQS
    ├── variables.tf
    └── outputs.tf         # README нет
```

**Хорошо:**

```text
modules/
├── network/
│   ├── README.md
│   ├── main.tf
│   ├── variables.tf
│   └── outputs.tf
└── orders_queue/
    ├── README.md
    ├── main.tf
    ├── variables.tf
    └── outputs.tf
```

````markdown
# orders_queue

Создаёт очередь SQS для заказов вместе с очередью недоставленных сообщений.

## Входы
| Имя | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | string | — (обязательно) | Имя очереди |
| `owner` | string | — (обязательно) | Значение тега `owner` |
| `cost_center` | string | — (обязательно) | Значение тега `cost_center` |

## Выходы
- `queue_arn` — ARN основной очереди

## Пример
```hcl
module "orders_queue" {
  source      = "./modules/orders_queue"
  name        = "orders"
  owner       = "team-payments"
  cost_center = "cc-1234"
}
```
````

## 6. Общие теги можно вынести в `locals` (можно)

**Правило.** Чтобы не повторять одни и те же теги в каждом ресурсе, их можно объявить один раз в `locals` и подмешивать через `merge`.

**Почему.** Так теги из правила 4 задаются в одном месте. Владельца или центр затрат меняют в одной строке, и про ресурс никто не забудет. Это только способ удобно выполнять правило 4, а не замена ему: тег `owner` и тег `cost_center` на каждом ресурсе по-прежнему обязательны.

**Плохо** (работает, но громоздко и легко разъезжается):

```hcl
resource "aws_sqs_queue" "orders_queue" {
  name = "orders"
  tags = { owner = "team-payments", cost_center = "cc-1234" }
}

resource "aws_sqs_queue" "refunds_queue" {
  name = "refunds"
  tags = { owner = "team-payments", cost_center = "cc-1243" }   # опечатка в центре затрат
}
```

**Хорошо:**

```hcl
locals {
  common_tags = {
    owner       = "team-payments"
    cost_center = "cc-1234"
  }
}

resource "aws_sqs_queue" "orders_queue" {
  name = "orders"
  tags = local.common_tags
}

resource "aws_sqs_queue" "refunds_queue" {
  name = "refunds"
  tags = merge(local.common_tags, { purpose = "refunds" })
}
```

## Всё вместе

Пример, в котором соблюдены все правила:

```hcl
terraform {
  required_providers {                                # правило 1
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.40"
    }
  }

  backend "s3" {                                      # правило 3
    bucket  = "brannock-tfstate"
    key     = "platform/orders/terraform.tfstate"
    region  = "eu-central-1"
    encrypt = true
  }
}

locals {                                              # правило 6
  common_tags = {
    owner       = "team-payments"
    cost_center = "cc-1234"
  }
}

resource "aws_s3_bucket" "orders_archive" {           # правило 2
  bucket = "brannock-orders-archive"
  tags   = local.common_tags                          # правило 4
}
```

## Чек-лист для PR

- [ ] У каждого провайдера в `required_providers` есть `version` с оператором `~>`.
- [ ] Локальные имена всех ресурсов записаны в `snake_case`.
- [ ] В диффе нет `*.tfstate` и `*.tfstate.*`, а backend удалённый.
- [ ] У каждого ресурса есть теги `owner` и `cost_center` (напрямую или через `locals`).
- [ ] Новый модуль лежит в отдельном каталоге и с README (желательно).

---

Я не добавлял правил сверх ваших. Два места я оставил открытыми и в документе не решал:
- **Ресурсы без тегов.** Часть ресурсов не поддерживает теги. Правило 4 сформулировано как «у каждого ресурса, который поддерживает теги». Стоит договориться, как оформлять такие случаи.
- **`.terraform.lock.hcl`.** Он не является state, и правило 3 на него не распространяется. Коммитить его или нет, вы не обсуждали.
