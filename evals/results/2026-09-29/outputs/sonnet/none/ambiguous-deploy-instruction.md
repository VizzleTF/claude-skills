# Деплой Moorfen API

## Общая схема

1. Push тега `vX.Y.Z` запускает CI, который собирает образ и **автоматически** выкатывает его в **stage**.
2. Выкатка в **prod** происходит только после ручного подтверждения: кнопка `promote-prod` в CI.
3. После выкатки проверяем `healthz`.

## Окно выкатки в prod

- Дни: понедельник – четверг.
- Время: 10:00 – 17:00 по Москве (MSK).
- Вне окна `promote-prod` завершится ошибкой (см. «Что обычно ломается»).

## Порядок деплоя

### 1. Выкатка в stage

1. Убедитесь, что тег соответствует шаблону `vX.Y.Z` (например, `v1.2.3`). Теги вида `v1.2` пайплайн не запустят.
2. Создайте и запушьте тег:
   ```
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```
3. Дождитесь, пока CI соберёт образ и выкатит его в stage.

### 2. Выкатка в prod

1. Убедитесь, что сейчас рабочее окно (пн–чт, 10:00–17:00 MSK).
2. В CI нажмите `promote-prod` для нужного тега.

### 3. Проверка после выкатки

```
curl -fsS https://moorfen.example/healthz
```

Ожидаемый ответ: `ok`. Любой другой ответ считается неуспешной выкаткой (см. ниже).

## Откат

Перезапустите `promote-prod` у **предыдущего** тега. После отката повторите проверку `healthz`.

## Что обычно ломается

| Симптом | Причина | Что делать |
|---|---|---|
| `promote-prod` падает с `deploy window closed: allowed Mon-Thu 10:00-17:00 MSK` | Запуск вне окна выкатки | Дождаться окна и перезапустить `promote-prod`. |
| Пуш тега не запускает пайплайн, ошибок нет | Тег не по шаблону `vX.Y.Z` (например, `v1.2`) | Удалить тег: `git push --delete origin <TAG>`, затем запушить правильный тег. |
| `healthz` отвечает `degraded: db` вместо `ok` | Сервис не видит базу | Откатиться через `promote-prod` предыдущего тега и написать в #moorfen-dev. |
| Сборка падает с `COPY failed: file not found in build context` | В репозитории нет файла, на который ссылается Dockerfile | Исправить пути в Dockerfile и запушить исправление **с новым тегом**. |
