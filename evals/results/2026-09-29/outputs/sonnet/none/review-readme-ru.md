# Ревью README.md проекта Brinebak

Файл маленький (27 строк) и читается за минуту, но новичок по нему не сможет установить и запустить утилиту. Сверял с фактами: Brinebak делает бэкапы PostgreSQL по расписанию в S3-совместимое хранилище, пакет на PyPI называется `brinebak-cli`, нужен Python 3.10+, минимальный запуск — `brinebak run --config brinebak.yaml`.

## Критичные

### 1. Неверное имя пакета в установке (строка 17)
- **Проблема:** `pip install brinebak` ставит не тот пакет. В лучшем случае команда упадёт с ошибкой. В худшем поставится чужой пакет с похожим именем, а это риск для безопасности.
- **Исправление:** заменить на `pip install brinebak-cli`.

### 2. Не указана версия Python (раздел «Установка»)
- **Проблема:** про Python 3.10+ нигде не сказано. На 3.8 или 3.9 установка упадёт или пройдёт с непонятной ошибкой.
- **Исправление:** добавить строку перед командой установки, например «Требуется Python 3.10 или новее».

### 3. Нет запуска (во всём файле)
- **Проблема:** после установки непонятно, что делать. Команда `brinebak run --config brinebak.yaml` в README отсутствует.
- **Исправление:** добавить раздел «Быстрый старт» сразу после установки. Он должен включать команду запуска и одну-две фразы о том, что она делает: запускает планировщик, делает один бэкап или что-то ещё. Об этом ниже, в проблеме 9.

### 4. Раздел «Настройка» пустой (строки 20–22)
- **Проблема:** «Создайте файл конфигурации… Подробности смотрите в документации» — это отсылка в никуда. Файл не назван, формат не указан, параметры не перечислены, ссылки на документацию нет. Запуск из проблемы 3 требует `brinebak.yaml`, и читатель не знает, что в нём писать.
- **Исправление:** дать минимальный рабочий `brinebak.yaml` и пояснить каждый ключ. Как минимум это:
  - подключение к PostgreSQL;
  - endpoint, бакет и учётные данные S3;
  - расписание.

  Актуальные имена ключей нужно взять из кода или схемы конфига. Если документация существует, поставить на неё реальную ссылку.

## Существенные

### 5. Вступление не отвечает на вопрос «что это» (строки 3–5)
- **Проблема:** первый абзац — история команды («всё началось в 2023 году…»), второй — общие слова про «философию» и «бесшовную» интеграцию. Что именно делает Brinebak, читатель узнаёт только из списка на строках 9–10. Утверждения вроде «самое ценное, что есть у компании» и «бесшовно встраивается» ничего не сообщают и не проверяются.
- **Исправление:** открыть README одной фразой о том, что это. Например: «Brinebak — утилита для резервного копирования PostgreSQL по расписанию в S3-совместимое хранилище». Историю убрать или сократить до одной строки в конец. «Философию» и «бесшовность» удалить.

### 6. В списке возможностей есть пункты, которых нет в справке (строки 11–12)
- **Проблема:** «Шифрование снапшотов» и «Проверка восстановления» не подтверждены и в опорных фактах о продукте не упомянуты. Если функций нет или они не готовы, README обещает лишнее. Если они есть, то не описано, как их включить, а без этого пункты бесполезны.
- **Исправление:** сверить пункты с кодом. Несуществующие удалить. Существующие оставить и дать по одной строке о том, как включаются, например какой ключ конфига отвечает за шифрование и откуда берётся ключ.

### 7. Нет ссылок и нужных для старта сведений
- **Проблема:** «Пишите в issues» (строка 26) без ссылки. Не указаны репозиторий, документация, лицензия, способ внести вклад. Нет предварительных требований: доступ к PostgreSQL, права пользователя БД, бакет S3.
- **Исправление:**
  - сделать ссылку на страницу issues;
  - добавить ссылки на документацию и лицензию;
  - добавить короткий список «Что понадобится» перед быстрым стартом.

## Мелкие

### 8. Термин «снапшот» размыт (строки 9 и 11)
- **Проблема:** в PostgreSQL и S3 «снапшот» обычно означает снимок диска или тома. Судя по описанию, Brinebak делает резервные копии базы, а не снимки томов. Читатель может неверно понять, что именно сохраняется.
- **Исправление:** использовать «резервные копии» или «бэкапы». Если это логический дамп (`pg_dump`) или физическая копия, так и написать. Тип копий нужно подтвердить по коду.

### 9. Не объяснено, как работает «по расписанию»
- **Проблема:** неясно, где задаётся расписание и что делает `brinebak run`: держит процесс и сам запускает бэкапы по расписанию или делает один бэкап и выходит, а расписание нужно ставить через cron или systemd. От этого зависит, как читателю запускать утилиту в продакшене.
- **Исправление:** одной-двумя фразами в быстром старте описать поведение `run` и показать, где задаётся расписание. Если поддерживаются оба режима, описать оба.

### 10. Нет сведений о восстановлении
- **Проблема:** утилита для бэкапов, а в README ни слова о том, как из копии восстановить базу. Это первый вопрос, который задаст разработчик, оценивающий инструмент.
- **Исправление:** добавить раздел «Восстановление» или ссылку на него. Если команды восстановления пока нет, честно сказать об этом.
