```markdown
# ADR-0015: Хранить пользовательские сессии в PostgreSQL

- Статус: принято
- Дата: 2026-09-28
- Заменяет: [ADR-0007](ADR-0007-sessions-in-redis.md)

## Контекст

Сервис Varnholt хранит сессии пользователей в отдельном кластере Redis 7 по решению ADR-0007. Этот кластер выводим из эксплуатации до 2026-12-01, чтобы сократить расходы. В 2025 году таблицу в PostgreSQL отклонили, потому что основной кластер PostgreSQL работал на пределе по записи. В 2026 году аналитику перенесли в отдельное хранилище, и нагрузка на запись в PostgreSQL снизилась.

## Решение

Мы будем хранить сессии в таблице `sessions` в существующем PostgreSQL 16. Время жизни сессии остаётся прежним: 14 дней, продлевается при каждом запросе. Устаревшие сессии удаляет задача `pg_cron` раз в 10 минут.

## Последствия

Команда платформы больше не сопровождает отдельный кластер Redis. Чтение сессии медленнее: 3,1 мс на p99 против 0,8 мс в Redis, что укладывается в бюджет 20 мс. Продление сессии на каждом запросе означает запись в PostgreSQL на каждый запрос.

## Альтернативы

- Оставить сессии в Redis отклонено: кластер Redis выводим из эксплуатации ради сокращения расходов.
- Липкие сессии на балансировщике отклонены по той же причине, что в ADR-0007: при отказе экземпляра сессия теряется.
```
