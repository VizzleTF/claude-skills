# Hollin — сервис уведомлений

Hollin отправляет уведомления пользователям по email, SMS и push. Сервис принимает один запрос: какой канал использовать, кому отправить, какой шаблон взять и что в него подставить. Если доставка не удалась, Hollin сам повторяет попытки.

## Как подключиться

1. **Получите доступ к API.** **[уточнить: куда писать, как выдаются ключи или токены, как передавать их в запросе]**
2. **Подготовьте шаблон.** Шаблоны хранятся в Git-репозитории [`hollin-templates`](**[уточнить: ссылка]**). Если нужного шаблона нет, добавьте его. **[уточнить: через merge request, кто ревьюит, сколько ждать]**
3. **Отправьте уведомление** через `POST /v1/notifications` (см. ниже).
4. **Учтите лимит:** не больше 50 запросов в секунду на клиента.

## API

### `POST /v1/notifications`

Отправляет одно уведомление.

| Поле | Описание |
|---|---|
| `channel` | Канал доставки: email, SMS или push. **[уточнить: точные значения, например `email` / `sms` / `push`]** |
| `recipient` | Получатель. **[уточнить: формат для каждого канала — адрес, номер телефона, device token или ID пользователя]** |
| `template_id` | Идентификатор шаблона из репозитория `hollin-templates`. |
| `params` | Значения для подстановки в шаблон. |

Пример запроса (значения условные):

```http
POST /v1/notifications
Content-Type: application/json

{
  "channel": "email",
  "recipient": "user@example.com",
  "template_id": "order-confirmation",
  "params": {
    "order_number": "12345",
    "user_name": "Анна"
  }
}
```

## Ограничения

- **Лимит запросов:** 50 в секунду на клиента. **[уточнить: что происходит при превышении — например, код `429` — и нужно ли клиенту повторять запрос самому]**
- **Повторы доставки:** если уведомление не доставлено, Hollin повторяет попытку три раза: через 1, 4 и 16 секунд. Всего получается до четырёх попыток примерно за 21 секунду. Повторять запрос на своей стороне из-за сбоя доставки не нужно, Hollin уже делает это сам. **[уточнить: что происходит после последней неудачной попытки — узнаёт ли об этом клиент]**

## Шаблоны

Все шаблоны уведомлений хранятся в Git-репозитории `hollin-templates`. Значение `template_id` в запросе должно совпадать с шаблоном из этого репозитория, а ключи в `params` — с переменными шаблона. **[уточнить: структура репозитория, язык шаблонов, как изменения попадают в прод]**

## Как устроен сервис

Hollin работает в Kubernetes в четырёх репликах.
