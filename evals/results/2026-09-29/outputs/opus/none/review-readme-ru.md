## Проблемы, от серьёзных к мелким

### 1. Неверное имя пакета в команде установки: команда из README не установит утилиту
**Где:** строка 17, `pip install brinebak`.
**Что не так:** на PyPI пакет называется `brinebak-cli`. Новый разработчик скопирует команду и получит ошибку или вообще чужой пакет.
**Как исправить:**
```bash
pip install brinebak-cli
```

### 2. Нет требования к версии Python
**Где:** раздел «Установка» (строки 14–18).
**Что не так:** не сказано, что нужен Python 3.10+. На старой версии пользователь получит непонятную ошибку при установке или при запуске.
**Как исправить:** перед командой установки добавить строку «Требуется Python 3.10 или новее».

### 3. Нет команды запуска
**Где:** во всём документе.
**Что не так:** после установки читатель не знает, как запустить утилиту. Минимальной команды `brinebak run --config brinebak.yaml` в README нет.
**Как исправить:** добавить раздел «Запуск»:
```bash
brinebak run --config brinebak.yaml
```
Рядом одной фразой пояснить, что делает команда: запускает бэкапы по расписанию из конфига или делает одну копию. Это нужно уточнить у авторов.

### 4. Раздел «Настройка» пустой: ни примера, ни имени файла, ни ссылки

- «Подробности смотрите в документации» ведёт в никуда: ссылки нет.

**Как исправить:** дать минимальный рабочий пример `brinebak.yaml` с комментариями к каждому полю и настоящую ссылку на полную документацию. Схему конфига я не знаю, поэтому в черновике ниже оставлен TODO. Реальные имена полей нужно взять из кода или схемы.

### 5. Первые абзацы не говорят, что делает утилита
**Где:** строки 3 и 5.
**Что не так:** README начинается с истории создания («Всё началось в 2023 году…»), потом идёт маркетинг: «целая философия», «данные — самое ценное», «бесшовно встраивается». Читатель дочитывает до конца вступления и так и не узнаёт главного: утилита делает резервные копии PostgreSQL по расписанию и складывает их в S3-совместимое хранилище.

### 6. В списке возможностей неясные термины и непроверенные пункты
**Где:** строки 9–12.
**Что не так:**
- «Снапшоты» в строках 9 и 11 расходятся с формулировкой «резервные копии». «Снапшот» можно понять как снимок диска или тома, а не дамп БД. Лучше использовать один термин.
- «Шифрование снапшотов» и «Проверка восстановления» названы, но не сказано, как их включить: по умолчанию или через параметр конфига. В фактах для сверки этих функций нет, поэтому их наличие стоит подтвердить у авторов.
- «Хранение бэкапов» — это жаргонный вариант того же понятия, что и «снапшоты».

**Как исправить:** везде писать «резервные копии». Для шифрования и проверки восстановления дать ссылку на соответствующий раздел документации или название параметра конфига. Если какой-то функции пока нет, убрать её из списка.
