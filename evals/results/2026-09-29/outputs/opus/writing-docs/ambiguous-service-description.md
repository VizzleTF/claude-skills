# Hollin

Hollin — сервис уведомлений команды коммуникаций. Он отправляет email, SMS и push по шаблону. Эта страница для продуктовых команд, которые хотят отправлять уведомления через Hollin.

## Как подключиться

1. Добавьте шаблон уведомления в Git-репозиторий `hollin-templates`.
2. Отправьте запрос `POST /v1/notifications` с каналом, получателем, ID шаблона и параметрами (см. «Формат запроса»).
3. Не превышайте 50 запросов в секунду.

## Формат запроса

`POST /v1/notifications`

| Поле | Что указать |
|---|---|
| `channel` | Канал доставки: email, SMS или push |
| `recipient` | Получатель уведомления |
| `template_id` | ID шаблона из `hollin-templates` |
| `params` | Значения, которые подставляются в шаблон |

```json
{
  "channel": "<канал>",
  "recipient": "<получатель>",
  "template_id": "<id шаблона>",
  "params": { "<ключ>": "<значение>" }
}
```

## Лимит запросов

На одного клиента — 50 запросов в секунду. Если планируете больше, заранее напишите команде коммуникаций.

## Повторная доставка

Если доставить уведомление не удалось, Hollin повторяет попытку сам, до трёх раз:

| Попытка | Через сколько после предыдущей |
|---|---|
| 1-й повтор | 1 с |
| 2-й повтор | 4 с |
| 3-й повтор | 16 с |

Последний повтор уходит примерно через 21 секунду после первой попытки.

## Кто отвечает за сервис

Команда коммуникаций. С вопросами о подключении, шаблонах и лимитах обращайтесь к ней.

---

Я написал страницу как инструкцию по подключению, потому что чаще всего к вам приходят продуктовые команды. Кое-что я намеренно оставил за рамками:

- **Kubernetes и четыре реплики** в документ не вошли. Продуктовой команде это для подключения не нужно. Лучше вынести в отдельную страницу для дежурных или в runbook.
- **Сведения, которых не хватает для подключения.** Я их не придумывал, но без них подключиться нельзя:
  - базовый URL и авторизация: как клиент получает доступ и как Hollin его опознаёт для лимита;
  - точные значения `channel` (`email`/`sms`/`push`?) и формат `recipient` для каждого канала;
  - формат ответа и коды ошибок, в том числе что вернёт сервис при превышении 50 запросов в секунду;
  - процесс добавления шаблона: нужен ли PR с ревью от команды коммуникаций, как связаны `template_id` и файл в репозитории;
  - как клиент узнаёт, что все три повтора не удались;
  - контакт команды: канал в чате или трекер.
- **Фраза «заранее напишите команде коммуникаций» в разделе о лимите** — это моё допущение. Если лимит не поднимают, удалите её.

Пришлите недостающее — допишу страницу, и пример запроса можно будет скопировать и отправить как есть.
