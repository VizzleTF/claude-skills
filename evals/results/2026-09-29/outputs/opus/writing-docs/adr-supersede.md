```markdown
# ADR-0015: Хранить пользовательские сессии в PostgreSQL

- Статус: принято
- Дата: 2026-09-28
- Заменяет: [ADR-0007](ADR-0007-sessions-in-redis.md)

## Контекст

По [ADR-0007](ADR-0007-sessions-in-redis.md) сессии Varnholt хранятся в отдельном кластере Redis 7. Чтобы сократить расходы, этот кластер выводим из эксплуатации до 2026-12-01. Сессии по-прежнему должны быть доступны любому экземпляру API.

В 2025 году PostgreSQL отклонили, потому что основной кластер работал на пределе по записи. В 2026 году аналитику вынесли в отдельное хранилище, и нагрузка на запись снизилась.

## Решение

Мы храним сессии в таблице `sessions` в существующем PostgreSQL 16. Время жизни сессии — 14 дней, продлевается при каждом запросе. Устаревшие сессии удаляет задача `pg_cron` раз в 10 минут.

## Последствия

- Чтение сессии занимает 3,1 мс на p99 против 0,8 мс в Redis. Это укладывается в бюджет 20 мс.
- Команда платформы больше не сопровождает отдельный кластер Redis.
- Продление на каждом запросе — это запись в PostgreSQL на каждый запрос.
- Если PostgreSQL недоступен, пользователи не могут войти.
- Сессии, истёкшие между запусками очистки, остаются в таблице до 10 минут.

## Альтернативы

- Оставить Redis — отклонено: кластер выводим из эксплуатации ради сокращения расходов.
- Липкие сессии на балансировщике — отклонено: при отказе экземпляра сессия теряется.
```
