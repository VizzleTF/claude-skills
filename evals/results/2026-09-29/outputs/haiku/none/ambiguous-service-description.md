# Hollin — Сервис Уведомлений

## Описание

Hollin — это централизованный сервис для отправки уведомлений по различным каналам. Сервис позволяет приложениям и микросервисам отправлять сообщения пользователям через email, SMS и push-уведомления через единый API.

## Основные возможности

- **Многоканальная доставка**: поддержка email, SMS и push-уведомлений
- **Единый API**: стандартизированный REST API для всех типов уведомлений
- **Управление шаблонами**: переиспользуемые шаблоны сообщений, управляемые через Git
- **Надёжная доставка**: автоматические повторы при сбое
- **Масштабируемость**: работает на Kubernetes с несколькими репликами

## API

### Endpoint

```
POST /v1/notifications
```

### Параметры запроса

| Параметр | Тип | Описание |
|----------|-----|---------|
| `channel` | string | Канал доставки: `email`, `sms` или `push` |
| `recipient` | string | Email, номер телефона или ID пользователя в зависимости от канала |
| `template_id` | string | Идентификатор шаблона сообщения |
| `params` | object | Параметры для подстановки в шаблон |

### Пример запроса

```json
{
  "channel": "email",
  "recipient": "user@example.com",
  "template_id": "welcome_email",
  "params": {
    "username": "john_doe",
    "activation_link": "https://example.com/activate/123"
  }
}
```

## Ограничения

- **Лимит частоты**: максимум 50 запросов в секунду на одного клиента
- При превышении лимита запросы получат ошибку 429 Too Many Requests

## Шаблоны

Шаблоны сообщений хранятся в Git-репозитории `hollin-templates`. Это позволяет:
- Версионировать изменения
- Проводить code review перед развёртыванием
- Откатываться к предыдущим версиям
- Централизованно управлять содержимым

## Обработка ошибок и повторы

Если доставка уведомления не удалась, сервис автоматически повторяет попытку:
1. Первый повтор: через 1 секунду
2. Второй повтор: через 4 секунды
3. Третий повтор: через 16 секунд

Если все три попытки не удались, уведомление считается недоставленным.

## Инфраструктура

- **Платформа**: Kubernetes
- **Реплики**: 4 экземпляра для обеспечения отказоустойчивости и распределения нагрузки
- **Availability**: сервис спроектирован для высокой доступности

## Владельство и контакты

**Команда-владелец**: Команда коммуникаций

Коротко: обращайтесь к команде коммуникаций для вопросов по конфигурации, проблемам с доставкой или добавлению новых шаблонов.

## Для кого это

Hollin предназначен в первую очередь для **продуктовых команд**, которые хотят отправлять уведомления своим пользователям. Это может быть:
- Приветственные письма при регистрации
- Уведомления о важных событиях
- Пин-коды и коды подтверждения
- Информационные сообщения

## Как начать

1. Обратитесь к команде коммуникаций для получения доступа
2. Изучите доступные шаблоны в репозитории `hollin-templates`
3. Интегрируйте вызовы `POST /v1/notifications` в ваше приложение
4. Мониторьте успешность доставки уведомлений
