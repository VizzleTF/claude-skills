- Правила относятся к Terraform-коду платформы Brannock
- Обязательно: версии провайдеров закреплены через ~> в required_providers; зачем — обновление провайдера не должно приезжать молча с очередным init
- Обязательно: имена ресурсов в snake_case; зачем — единый поиск по коду и по плану
- Обязательно: state не коммитится в репозиторий, он хранится в удалённом бэкенде; зачем — в state бывают секреты, и две копии state расходятся
- Обязательно: у каждого ресурса теги owner и cost_center; зачем — по ним считают расходы и ищут владельца
- Рекомендуется: один модуль на каталог и README в каждом модуле; зачем — модуль понятен без чтения кода
- Можно: общие теги выносить в locals; зачем — меньше повторов

Оформи наши договорённости по Terraform-коду платформы Brannock, чтобы новые люди в команде их соблюдали и понимали, почему они такие. Нужны примеры «плохо → хорошо».

Наши правила из обсуждения:

- Версии провайдеров всегда закрепляем через `~>` в `required_providers`. Иначе обновление провайдера приезжает молча с очередным `init`. Это обязательно.
- Имена ресурсов только в snake_case. Так поиск по коду и по плану работает одинаково. Обязательно.
- State в репозиторий не коммитим никогда, только удалённый бэкенд. В state бывают секреты, а две копии state расходятся. Обязательно.
- У каждого ресурса теги `owner` и `cost_center`. По ним считают расходы и ищут владельца. Обязательно.
- Желательно: один модуль на каталог и README в каждом модуле, чтобы модуль был понятен без чтения кода.
- Можно выносить общие теги в `locals`, чтобы не повторять их.
