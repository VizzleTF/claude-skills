# Fixes to writing-docs

The `technical-writing` and `technical-writing-ru` skills replace an earlier skill, `writing-docs`. A review of `writing-docs` found 16 defects. This page lists each defect, the section of each version that fixes it, and how.

In the last column, EN links to the English version and RU to the Russian one.

| # | Defect in writing-docs | How it is fixed | Where |
|---|---|---|---|
| 1 | The sources table reads Write the Docs' ARID as "no duplicates". | The rule "Self-contained page" expands ARID correctly: Accept (some) Repetition In Documentation. | [EN](../plugins/technical-writing/skills/write/SKILL.md#core-rules) · [RU](../plugins/technical-writing-ru/skills/write/SKILL.md#общие-правила) |
| 2 | "Every page is self-contained" conflicts with "no fact is duplicated". | Context and prerequisites are restated on each page. Normative facts (a default, a limit, a flag) live in one place and are linked. README, tutorial and runbook allow repetition in their "Differences from the core rules" sections. | [EN](../plugins/technical-writing/skills/write/SKILL.md#core-rules) · [RU](../plugins/technical-writing-ru/skills/write/SKILL.md#общие-правила) |
| 3 | The NN/g figures from 1997 (79/16, +124%) open the skill as its main argument. | The study is named with its setting, a promotional tourism site. Its figures are not used; scanning advice applies only to navigation text such as a README. | [EN](../plugins/technical-writing/skills/write/sources.md#sources-the-skill-does-not-rely-on) · [RU](../plugins/technical-writing-ru/skills/write/sources.md#на-что-скилл-не-опирается) |
| 4 | Hard limits without a source: "no longer than 25 words", "cut in half". | "Lengths are guides": every number carries a source or a "rule of thumb" mark. The edit pass uses King's "second draft is the first minus 10%" as a guide. `check.py` reports sentence length as a warning. | EN [rules](../plugins/technical-writing/skills/write/SKILL.md#core-rules), [workflow](../plugins/technical-writing/skills/write/SKILL.md#workflow) · RU [rules](../plugins/technical-writing-ru/skills/write/SKILL.md#общие-правила), [workflow](../plugins/technical-writing-ru/skills/write/SKILL.md#порядок-работы) |
| 5 | Williams, Pinker, Zinsser, Strunk & White, Minto, Redish, IBM DQTI, *Docs for Developers*, Nora Gal and Chukovsky are missing. | Each source has a row saying what the skill takes from it and which file uses it. Nora Gal and Chukovsky are listed in both sources files and applied only in the Russian style file, because each version covers the style of its own language. | EN [style](../plugins/technical-writing/skills/write/sources.md#style), [process](../plugins/technical-writing/skills/write/sources.md#process-and-quality) · RU [style](../plugins/technical-writing-ru/skills/write/sources.md#стиль), [process](../plugins/technical-writing-ru/skills/write/sources.md#процесс-и-качество) |
| 6 | The skill breaks its own bans: aphoristic headings such as "a heading is a map, not a joke", frequent dashes. | Aphorisms, `not X, but Y` and frequent dashes are cataloged as patterns to remove on review. The skill texts pass `check.py`: `dash-density` flags frequent dashes and `llm-marker` flags `not just … but` and `not only … but`. Aphorisms have no automatic check. | [EN](../plugins/technical-writing/skills/write/style/llm-patterns.md#sentence-patterns) · [RU](../plugins/technical-writing-ru/skills/write/style/llm-patterns.md#паттерны-предложений) |
| 7 | No stage before the first page: audience, plan, priority, test on a reader. | A doc-set branch covers audience, inventory, friction log, minimum set, priority, publishing, feedback and retirement, and ends with a plan format. | [EN](../plugins/technical-writing/skills/write/process/doc-set.md#audience) · [RU](../plugins/technical-writing-ru/skills/write/process/doc-set.md#аудитория) |
| 8 | No section on LLM writing patterns. | A catalog of content, sentence and formatting patterns and conversation residue, each with a fix. | [EN](../plugins/technical-writing/skills/write/style/llm-patterns.md#content-patterns) · [RU](../plugins/technical-writing-ru/skills/write/style/llm-patterns.md#паттерны-содержания) |
| 9 | Verbs get one line. | Separate sections on characters and actions, verbs and nominalizations, after Williams. | [EN](../plugins/technical-writing/skills/write/style/english.md#verbs) · [RU](../plugins/technical-writing-ru/skills/write/style/russian.md#глаголы) |
| 10 | No cohesion: known to new, the topic of a paragraph. | The style file explains the known-to-new order; the "Cohesion" core rule puts the topic of a paragraph in its first sentence. | [EN](../plugins/technical-writing/skills/write/style/english.md#known-to-new) · [RU](../plugins/technical-writing-ru/skills/write/style/russian.md#от-известного-к-новому) |
| 11 | The curse of knowledge gets one sentence; the checklist has no test on a live reader. | Step 8 of the workflow gives the draft to a cold reader: a subagent without conversation context or a person. | EN [style](../plugins/technical-writing/skills/write/style/english.md#classic-style-and-the-curse-of-knowledge), [workflow](../plugins/technical-writing/skills/write/SKILL.md#workflow) · RU [style](../plugins/technical-writing-ru/skills/write/style/russian.md#проклятие-знания), [workflow](../plugins/technical-writing-ru/skills/write/SKILL.md#порядок-работы) |
| 12 | No runbook, postmortem, design doc, conventions or docstrings, although the description names docstrings. | Each type has its own file with the same seven sections. The design doc is covered by the ADR, which adds "Alternatives considered". | EN [runbook](../plugins/technical-writing/skills/write/types/runbook.md#skeleton), [postmortem](../plugins/technical-writing/skills/write/types/postmortem.md#skeleton), [adr](../plugins/technical-writing/skills/write/types/adr.md#skeleton), [conventions](../plugins/technical-writing/skills/write/types/conventions.md#skeleton), [docstring](../plugins/technical-writing/skills/write/types/docstring.md#skeleton) · RU [runbook](../plugins/technical-writing-ru/skills/write/types/runbook.md#каркас), [postmortem](../plugins/technical-writing-ru/skills/write/types/postmortem.md#каркас), [adr](../plugins/technical-writing-ru/skills/write/types/adr.md#каркас), [conventions](../plugins/technical-writing-ru/skills/write/types/conventions.md#каркас), [docstring](../plugins/technical-writing-ru/skills/write/types/docstring.md#каркас) |
| 13 | No Russian typography: ё, «ёлочки», dash and hyphen, non-breaking space. | The Russian style file has the rules after Milchin. `check.py`, the same file in both versions, checks Russian text with `ru-quotes`, `ru-dash`, `ru-yo` and `ru-nbsp`. | [EN](../plugins/technical-writing/skills/write/scripts/check.py) · [RU](../plugins/technical-writing-ru/skills/write/style/russian.md#типографика) |
| 14 | Visual content comes down to "crop screenshots". | The "Visual content" rule says when a picture beats text, keeps diagrams as code, and asks for alt text, a text equivalent of each step, tables for data and captions that say what to notice. | [EN](../plugins/technical-writing/skills/write/SKILL.md#core-rules) · [RU](../plugins/technical-writing-ru/skills/write/SKILL.md#общие-правила) |
| 15 | The grep checks catch only sentences that fit on one line. | `check.py` parses Markdown into paragraphs and table cells, skips code, and splits sentences across line breaks. Tests in `tests/test_check.py` cover it. | [EN](../plugins/technical-writing/skills/write/scripts/check.py) · [RU](../plugins/technical-writing-ru/skills/write/scripts/check.py) |
| 16 | Diátaxis applied too strictly: "zero explanations" in a tutorial. | A tutorial keeps one or two sentences of explanation where a step would look arbitrary, with a link to the full explanation. | [EN](../plugins/technical-writing/skills/write/types/tutorial.md#differences-from-the-core-rules) · [RU](../plugins/technical-writing-ru/skills/write/types/tutorial.md#отличия-от-общих-правил) |
