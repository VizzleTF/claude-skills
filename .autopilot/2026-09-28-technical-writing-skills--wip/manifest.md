## Находки adversarial pass (глубина deep)

1. **Провал**: судья-модель любит длинные и структурированные тексты; таблица без поправки на длину и позицию не заслуживает доверия. → craft: рубрика с якорями на каждый балл, перемешивание порядка, длина в отчёте отдельной колонкой, пары для владельца.
2. **Столкновение R21 × R20/R18/R28**: маршрутизатор, ядро правил, workflow, чек-лист и таблица исключений в ~150 строк. → craft: исключения живут в файлах типов (раздел «Отличия от общих правил»), в SKILL.md — только маршрутная таблица и ядро.
3. **Столкновение R36 × «не дословный перевод»**: паритет проверяется по набору правил, а не по тексту. → craft: машинная проверка паритета по идентификаторам правил/разделов.
4. **Цена R57 × R65**: ~180 генераций и ~180 оценок на подписке, это часы. → раннер возобновляемый (кэш по хэшу сценария+участника+модели), параллелизм ограничен.
5. **Условие**: судья без эталонного ответа не проверит «фактическую точность». → craft: в каждом сценарии — входные факты и список проверяемых утверждений.
6. **Вторая неделя**: скилл меняется, прогон нужно повторять. → результаты по датам, раннер одной командой, сравнение с прошлым прогоном не требуется (YAGNI).
7. **Второй актор**: сторонний пользователь маркетплейса, у которого нет `~/.claude/skills/writing-docs`. → раннер пропускает участника с понятным сообщением; README объясняет.
