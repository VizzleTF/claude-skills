## Что должно заработать

Английская версия скилла получает `SKILL.md` (маршрутизатор, ядро правил, workflow с копируемым чек-листом, три ветки), `style/english.md`, `style/llm-patterns.md`, `process/doc-set.md`, `process/review.md` и `sources.md`. SKILL.md ссылается на 13 файлов `types/*.md`. Их пишет таск 05, но имена фиксированы спецификацией §2. Текст написан на английском, по правилам самого скилла.

## Из брифа, дословно

> «`SKILL.md` — маршрутизатор, ядро правил, общий workflow с копируемым чек-листом, ветки «создать / ревью / набор документов». Цель — около 150 строк, чтобы он целиком переживал автокомпакцию.»
> «Скилл выбирает тип по читателю и его состоянию, а не по названию, которое дал пользователь.»
> «`description` пишется от третьего лица и говорит, что делает скилл. Триггеры на русском и английском идут в `when_to_use`. Вместе не больше 1536 символов.»
> «Тексты самих скиллов соблюдают свои правила: без афоризмов, отрицательных параллелизмов («не X, а Y»), правила трёх, частых тире, нагнетания.»
> «Сомнительные источники (блоги-пересказы, SEO-статьи) не использовать. Цитаты и цифры сверять с первоисточником.»
> Дополнение: «Каждая только свой язык» — EN-версия содержит только английский стиль.

## Разделы спецификации

Истории 1–10, 14 (ядро), 18–22, 30–36, 40 (свои пункты); Решения §2, §2a, §3 (только вызов скрипта); бриф — разделы «Классификация», «Где общие правила ломаются», «Что новый скилл обязан исправить», «Исследование».

## Критерии приёмки

- [ ] SKILL.md: frontmatter `name: technical-writing`, `description` в третьем лице без триггеров, `when_to_use` с триггерами на английском и русском (включая «описание», «методичка», «инструкция», «ранбук», «ADR», «README», «документация», «доки»), вместе ≤ 1536 символов; тело ≤ 170 строк, цель 150
- [ ] SKILL.md содержит всё из §2: оси, таблицу выбора типа, таблицу «слово запроса → вопросы о читателе → типы», маршрут «тип → `types/<file>.md`» для 13 типов, три ветки, глоссарий терминов скилла, ядро (ARID в верной расшифровке, самодостаточная страница с допустимым повтором контекста, ответ первым с исключениями, связность и тема абзаца, визуальное содержимое), правило «файл типа главнее ядра», копируемый чек-лист workflow, вызов `python3 "${CLAUDE_SKILL_DIR}/scripts/check.py" <file>`, проверку холодным читателем, правило про несовпадение языка документа с языком версии
- [ ] `style/english.md`: Williams, Pinker, Zinsser, Strunk & White, Orwell по §2a; глаголы (отдельный раздел, не одна строка); «known → new»; номинализации; стоп-слова по категориям; ориентиры длины с источником или пометкой «rule of thumb»
- [ ] `style/llm-patterns.md`: каталог по Wikipedia «Signs of AI writing» с примерами было → стало; явно афоризмы, «not X but Y», правило трёх, частые тире, нагнетание, метадискурс, оговорки, оценки вместо фактов
- [ ] `process/doc-set.md` (аудитория, инвентаризация, приоритет, friction log, минимальный набор, публикация, обратная связь, метрики, поддержка и списание) и `process/review.md` (порядок, 9 характеристик IBM DQTI, 7 признаков Baker, формат отчёта «где → что → как исправить»)
- [ ] `sources.md`: каждая строка таблицы источников брифа — библиография, что взято, где в скилле; NN/g, если упомянут, — с контекстом (1997, промо-сайт); ни одной цитаты или цифры, не сверенной с доступным первоисточником (непроверяемое — пересказом без кавычек и цифр)
- [ ] Никаких ссылок из `style/` и `process/` на другие файлы скилла; файлы > 100 строк начинаются с оглавления; нет дат, которые протухнут
- [ ] `check.py` из таска 01 (если уже есть) или ручной проход: без афоризмов, «not X but Y», правила трёх, частых тире; каждый файл — один термин на одно понятие по глоссарию
